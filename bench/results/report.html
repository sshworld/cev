6. Decision aids

Jev's three question types are kept as-is, plus six more aids for decision quality.

JEV · 1

Yes/no (bool)

Returns a single probability of YES. "Is it safe to delete?", "Should this be blocked?"

JEV · 2

Choice (choice)

One of a fixed set of options, with a probability per option. Routing, classification

JEV · 3

Score (score)

A position on a fixed scale, with a probability per level. Rubric grading

CEV · added

Abstain + missing info

Every question has an "abstain" option; choosing it means stating what's missing. Keeps the model from forcing a guess

CEV · added

Evidence quote check

The model must quote evidence verbatim from the situation, and code checks that the sentence actually exists

CEV · added

Risk-based thresholds

Each question is tagged low / medium / high. Confidence below 0.6 / 0.75 / 0.9 respectively goes to a human

CEV · added

Rule list

Decision criteria are sent separately from the situation. The same rules can judge many situations, and you can change only the rules and re-evaluate

CEV · added

Two-model cross-check

If Claude and Codex answer differently, it escalates regardless of confidence. Guards against one model's confident mistake

CEV · added

Decision log

The request and both models' answers are written to ~/.cev/log.jsonl, which becomes the next eval set as-is

Reading these results

  • The decision problems and answers were written by me (Claude). They're designed to be answerable from the rules alone, but there may be a bias in Claude's favor.
  • 30 decisions is a small sample. Look at the large differences (total tokens, latency, whether wrong answers occur) rather than individual percentages.
  • Token counts are as reported by the CLIs. Main-conversation tokens are estimated: character count times a measured ratio (0.40 tokens per character).
  • Baseline output includes the currently enabled output style (Learning, with insight blocks). It was left on because that matches real sessions.
  • Runs use subscription quota. Timings vary with network and server load, and include the few seconds spent launching a fresh process per call.
